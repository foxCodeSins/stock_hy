## 修复：腾讯日K WAF 限流误报与健康状态（15:47）

- 用户反馈健康面板显示「腾讯证券日K(前复权) 异常 · 腾讯日K两个域名均不可用（可能被 WAF 限流）」。
- 诊断：备用源 `sinaKline` 其实已接管（返回 91 根），但 health 把「主源失败」直接标成「异常」误导用户；且 `meta.klineSource` 仍显示腾讯前复权（`lastKlineSource` 在缓存命中时不更新，与实际口径不符）。
- 根因：腾讯 WAF 对**短时间高频日K请求**临时封禁（HTTP 501），冷却后带不带 `_=timestamp` 都恢复 200 —— 不是参数问题，是频率。各模块分别用 limit 90/120 建缓存键，同一只股票被重复拉取，缓存过期时批量并发打向腾讯。
- 修复（`lib/datasource.js`）：
  - **WAF 熔断**：两个域名全失败 → `tencentBlockedUntil = now + 120s`；冷却期直接走备用源、零腾讯请求；到期自动探活，恢复前复权口径。health 标 `degraded:true` + `sourceLabel` + `resumeAt`。
  - **limit 归一化**：≤120 一律取 120 根并统一缓存键 `klineData:<sym>:120`，dashboard / pullback / backtest / dragon 共享缓存，请求量减半；缓存 TTL 5→10 分钟。
  - 日K URL 去掉 `&_=Date.now()`（本身有服务端缓存，随机参数只会增加 WAF 穿透特征）。
  - `getKlineData` 缓存命中也更新 `lastKlineSource` 并 `noteKlineSource`；`getKlineSource()` 改为近 1 分钟各源计数统计，混用时如实列出「主源（混用 备用源×N）」，不再只报最后一次成功源。
- 前端：health 渲染支持 `degraded` —— 黄点 + 「已降级」标签 + 「降级 · 冷却中/备用源接管」文案 + 口径提示 note-box（说明不复权口径对历史划线/支撑位/回撤测算的影响、2 分钟冷却自动探活）；不再显示旧的「异常 · 腾讯日K两个域名均不可用」。CSS 新增 `.hdot.warn`。
